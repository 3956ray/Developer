## 4. 业务登录、会话与operator生命周期

### 4.1 登录与会话

用户主动选择登录，阅读适用的数据处理说明后，客户端`wx.login`的code送本应用服务端；服务端调用微信code2Session并校验业务成功，再建立该AppID下的微信身份→随机业务userId映射，签发至少256位安全随机的不透明业务令牌。服务端只存令牌摘要及sessionId／userId／authAt／createdAt／lastInteractiveAt／expiresAt／revokedAt；完整令牌仅返回本人客户端一次并放入本应用私有缓存，不写日志、分享链接或公共页面。AppSecret、session_key和微信access_token只在服务端，不作为业务令牌。UnionID不作为必需条件。[官方依据](../../raw/SRC-20260916-gym-wechat-01.md)

空闲期限只由有效的主动业务动作延长（本人主动查看／操作或维护写入），定时轮询不延长；绝对期限固定。过期、撤销或无效令牌统一401，客户端清理个人缓存，公共浏览继续；不能回退假登录。退出登录撤销当前会话并清缓存；删除账户撤销全部会话。多设备会话可并存，但每用户最多5个有效会话，第6个新登录在事务中撤销最早建立的会话；权限实时来自数据库而非令牌自报。

code一次使用。登录响应丢失时重新主动获取新code，不用旧code重放；该登录可能留下未取到令牌的孤立会话，受上述上限与到期清理约束，不能因此出现多份业务身份。登录和账户创建按微信身份映射唯一约束处理并发；账号删除与该账号写操作串行检查状态，不允许在删除提交后对旧userId写入。删除后新的主动登录仅创建新随机userId，无旧绑定或角色继承。

### 4.2 operator授予／撤销

CP1提供一个最小服务端管理命令／操作流程，由已授权部署维护者执行；不新增客户端授予接口或通用权限后台。参数为现有业务userId、唯一gymId、grant/revoke和原因；真实环境操作前需要负责人确认该人是馆方授权人员。作用域与执行人记入审计，执行结果可查询，操作不得包含AppSecret或会员原始凭证。

所有管理读写先校验业务会话、账号状态及当前角色表。撤销提交后，旧令牌可以继续作为普通用户使用，但下一管理请求必须403；缓存角色不能延迟撤销。授予和撤销以及并发管理写入以同一角色版本／事务锁顺序处理：撤销之前已提交的写入保留；撤销之后未提交的写入必须失败，无部分写入。删除账户同样清除operator角色，重新登录不恢复；测试名单与门店名单隔离。

### 4.3 限流：固定窗口、持久化、明确作用域

10分钟类窗口按服务端UTC Unix秒对600秒取整，登录交换独立按60秒取整；均为固定窗口，不滑动清零。命中上限返回429及`retryAfterSeconds`，到下一窗口允许重试。计数保存在正式数据库并原子递增，重启／多进程／重新登录不重置；限流存储不可用时相关写／登录暂时不可用，不降级内存放行。到窗口结束后1小时方可清理桶。前台倒计时不替代服务端校验。

| 动作 | 作用域与上限 | 何时计数 |
| --- | --- | --- |
| 新登录交换 | 单店部署全局每分钟120次，60秒固定窗口；所有环境分别计数 | 新code交换尝试计数；平台失败也计入；无用户身份时不假装按openid限流；不新增IP或设备追踪 |
| 生成／重建配对请求 | `gymId + userId`，每10分钟3次 | 同幂等key重放不计；首次被接受的新请求计，失败碰撞耗尽不消耗现有请求 |
| operator查询／绑定失败 | `gymId + operatorUserId`，每10分钟最多5次错误；定位到真实请求时，另按`gymId + requesterUserId`累计5次错误 | 无效／过期／已消费／核验不匹配计；并发版本冲突、服务器故障不计。未知码无法定位用户时只计操作者，不漏记、不凭码暴露他人信息 |

同一账号解除绑定、删除后新建可能改变userId，不把限流当作实体反滥用或防重复资格的唯一措施；真实资格始终需馆方核验和当前会员登记约束。由于operator是受控人员，首版不用复杂风险评分系统。

## 5. 人工忙闲闭环

单店当前观察由单调递增`observationRevision`保护。operator现场观察后选择`quiet/moderate/busy`，确认刚观察并提交；也可发布`unknown`、`paused`控制状态或撤销当前记录。每次动作包含当前expectedRevision、幂等key、requestCreatedAt。服务端提交时产生observedAt／publishedAt（本版二者为同一提交时刻）、validUntil=observedAt+900秒及作者。观察提交超过60秒未明确成功时，先查原操作；没有提交则必须重新观察并以新操作提交，不能用离线队列事后假装刚观察。

较空＝约定观察点基本无等待；适中＝部分需要轮换；较忙＝多处持续等待。观察点由馆方在CP7前核定至少3处，含力量／有氧使用情况；未巡视、冲突明显或无法判断时发布unknown。不能用面积、器械数、课程人数、门禁开门次数推断等级或人数。维护端提示观察剩余有效时间，但本版不依赖通知或后台定位。

| 数据／网络状态 | 主展示与行为 |
| --- | --- |
| 有效人工记录 | “馆方现场观察 · 较空/适中/较忙”；显示日期／时间、距今及有效性，不显示人数 |
| 到900秒边界 | “忙闲信息已过期”；旧等级仅弱化为历史，不能继续绿色新鲜主卡 |
| 无记录／unknown／paused／withdrawn | 对应“尚未更新／暂无法判断／暂停更新／记录已撤回”；撤销不回退旧记录 |

| 网络失败 | 明确连接失败；缓存只作为上次获取的记录，保留原时间；不知道年龄就不能标新鲜 |
| 闭馆 | 依据已核实营业配置显示闭馆；不自动造0人或零点清空观察 |

GET、刷新、重新启动、修改文案／课表、清理历史都不能增加观察TTL或回退revision。清理后仍保留当前指针／撤销标记，避免历史记录被重新选为当前。真实环境拒绝`simulation`模式和任何numeric occupancy字段；测试环境可显示醒目“模拟数据”用于状态验收。

## 6. 会员核验、状态与重新绑定

### 6.1 数据与信任来源

微信业务身份不证明自然人实名或健身房会员。会员入口的有用结果是本人可见馆方核验的关系／资格状态、核验时间及明确有效期，能办理重核验、撤销／解绑与账户删除。原系统仍为会员资格的业务依据，本系统不自动开门、收款或同步原馆权益。

馆方在原系统核验时录入本店稳定的会员引用，服务器只持久化`memberKey=HMAC(门店稳定密钥, 规范化会员引用)`用于唯一性、当前资格和撤销防回生检查；原始引用仅在本次授权提交中处理，不落日志、审计或幂等响应正文。会员引用按首店约定只去首尾空格、保留大小写与前导0，不猜测数字等价；CP7确认原系统引用规则后固定。门店HMAC密钥与AppSecret分离，重启不变；密钥缺失时停止核验，不换新密钥绕过原唯一性。它仍是可关联个人的假名数据，不宣称匿名。

会员登记`MemberRegistry`存memberKey、资格状态／期限模式、verifiedAt及revision；当前关联`Binding`存userId、memberKey及关系状态，数据库约束一个memberKey最多一个当前关联、一个userId每店最多一个当前关联。历史解除／撤销不能当有效关联。资格登记与微信关联分离，避免解绑／删除绕过撤销。

### 6.2 配对请求与一次消费

未绑定／已解绑用户，或当前关联已撤销且需要重新核验的本人，可以生成请求；有效关联本人不得借新请求抢占另一会员。8位随机码按门店在所有未到期可用请求中唯一，数据库唯一约束／事务处理并发。使用安全随机源，遇碰撞重新抽取，最多5次；耗尽返回503，整个事务回滚，原请求继续有效。客户端不能自选码。服务端保存带门店密钥的查询HMAC及短时加密展示副本；原码不以明文保存或写日志，加密副本最多保留到600秒到期且清理在下个小时内完成。有效配对码仅其本人经鉴权可取，operator按提交码查询待核验请求，查找结果只显示核对所需信息，不返回微信身份。

重建请求在一个事务里使旧请求失效并创建新请求；同key重试返回同一仍有效请求，而不是再生成码。到期／已取消／已消费后重试查询只返回其终态，不重新展示可用码。operator须当面比对当前请求与用户端，再核对原系统允许的会员凭据；仅知道码不能完成绑定。

绑定确认必须提交当前配对请求版本、会员登记版本（新登记显式expected absent）、原系统核验确认和有效期模式。事务重检账号、operator、请求有效性、会员登记状态、唯一性，成功时同时写Binding、资格记录、消耗请求和审计。已被其他账号绑定、并发消费或版本变化返回409，不自动覆盖。

### 6.3 有效期、撤销及状态优先级

期限模式为`fixed_until`（必有UTC到期时刻）、`no_fixed_expiry`（馆方显式确认）、`pending_confirmation`（具体期限依据不足）。固定日期型会员按馆方确认的门店本地有效结束日期**次日00:00排他**转换，页面同时显示原本地日期，不能默认为当天00:00过期。无固定期限不由null推断。每次请求按服务端时间计算到期，无需定时任务才能撤销资格。

页面状态按以下顺序合成：账号删除/无有效会话→未登录；无当前Binding→待核验或未绑定/已解绑；当前Binding被撤销或MemberRegistry为revoked→已撤销；关系已核验但期限待确认→已核验、有效期待确认；fixed_until且now≥截止→过期；其余有明确有效依据→有效。已撤销优先于旧未来到期日，MemberRegistry撤销不能被新Binding覆盖。

普通本人可查看自己有效／过期／撤销的最小状态，不能查看其他会员；“待确认”不授予未来会员专属权限。首版不新增额外会员权益，任何状态均不成为operator。敏感写入每次服务端重检，页面显示旧有效不构成授权。

| 动作 | 服务端规则 |
| --- | --- |
| operator撤销会员 | 设置当前资格revoked并标记当前关联撤销，写原因；该关联仍为占据唯一性槽位的当前关联，页面显示已撤销。下一请求不得按有效会员授权，但本人查询状态、取消/新建待核验请求、解绑/删除及operator显式重核验仍允许 |
| 已撤销会员重新申请 | 允许生成新的待核验请求，普通bind始终拒绝恢复revoked。operator显式选择“重新核验恢复资格”，核对当前原系统证据并提交配对、Binding与Registry三个expected revision；同一事务将本人同一当前Binding恢复为已核验、更新Registry期限/资格、消费配对并写审计。不得先恢复Registry再用第二次非原子请求绑定 |
| 续期／期限确认 | operator重新核验并按当前revision更新；不能用用户勾选或仅新登录续期；同一当前关联仍可保留 |
| 本人取消配对 | 请求进入cancelled，不影响原馆合同；之后可新建，旧码永远不能再次消费 |
| 本人解绑 | 5分钟内重新认证且确认；解除当前Binding并使其待配对请求失效；资格登记保留最小状态，不在新申请时自动绑定 |
| 解绑后再次绑定 | 必须新配对＋前台重新核验；原始撤销标记仍有效，不能把同一微信登录当已核验 |
| 删除后新登录 | 创建新业务userId，无绑定／operator；即便输入同一会员引用，也需全套重核验。没有当前Binding但Registry仍revoked时，显式恢复流程以Binding expected absent原子创建新关联，其余核验/消费/审计同上；不能普通bind恢复资格 |

账户删除、会员撤销、解绑、绑定确认的事务统一重检当前账号／Binding／MemberRegistry版本。若删除或撤销先提交，旧请求不得提交绑定；若绑定先提交，后续删除／撤销必须清掉其作用，不允许孤立有效关联。旧操作响应迟到时只展示已提交操作历史，并重新取当前状态，不将页面恢复为有效。

若同memberKey仍被**另一个userId**的当前关联占据（包括已撤销），恢复／绑定都返回409，不自动转移。旧关联须先由原本人解绑／删除而关闭，再对新账号全套核验；本版不实现绕过原账号的自助抢回或会员转让流程。显式恢复请求也受当前账号/operator、限流、幂等和并发控制，不是特殊放行通道。

## 7. 课表、门店时区与发布冲突

维护端编辑单一可变草稿，课程含稳定courseId、名称、startAt、endAt、scheduled/cancelled及revision；教练、容量、出席人数非P0字段。草稿不可被公共API返回。课程时间start<end；本地时间先按门店IANA时区转换UTC；夏令时不存在或重复的本地时间输入拒绝并要求明确偏移，不能自动猜测。测试配置不等于实际门店时区；一旦已有发布，时区只读，变更须明确撤回、重新换算并重发，不静默修改历史时刻。

本版每店仅**一个当前课表发布快照**：coverageStartDate含、coverageEndDate不含（门店本地日期），覆盖长度1–14天，courses为该范围的完整集合。每次发布同时提交expectedPublicationRevision和expectedDraftRevision，事务验证后整体替换当前快照；同一版本并发只有一个成功，另一个409，不能自动合并为重叠发布。替换导致某日期退出覆盖时，该日期成为尚未发布，不继续展示旧快照。发布时明确提示将替换的覆盖范围。

课程需与覆盖区间相交才能发布，跨边界课程可包含完整起止时间；查询某天／周按区间重叠，跨午夜／周一进行中不会消失。取当天开始≤now<结束判断正在排课；取消课不作为当前进行中。改期保留courseId，取消保留cancelled标记和修订；草稿操作不影响现行课程直到发布。单瑜伽室内scheduled课程相互重叠会阻止发布，要求更正；不允许用分房或多资源调度扩范围。

没有覆盖→“课表尚未发布”；覆盖内courses为空→“该日无排课”；有课→列表与按课表摘要；撤回→“课表已撤回”；网络失败→旧缓存明确“未能确认最新变更”。coverage不是忙闲TTL，不在15分钟后失效；覆盖外或撤回时不复用上周表。无排课不等于实际空闲／允许进入。现在没有真实课表可完成工程功能，但门店环境不得预置合成课程。

## 8. 统一API行为、持久化与失败重试

CP0可选择技术语言、数据库和路由名称，但必须提交覆盖下列业务动作的接口清单、请求／响应字段、错误码及事务边界，与本文行为一致。所有业务数据在真实持久化数据库中，不能只用内存或客户端storage；测试与门店使用独立数据与密钥，明确environment并拒绝跨环境身份。

| 类别 | 必需行为 |
| --- | --- |
| 公共读 | 场馆快照、当前观察、按日期范围查询已发布课表，附serverNow、revision、来源和可用状态；不带actor个人标识或微信映射 |
| 登录／本人 | 官方交换适配器、显式测试替身、会话状态/登出、本人会员/配对、取消请求/解绑/账户删除与删除状态 |
| 管理 | 当前角色查询；观察写/暂停/撤销；会员请求查询/核验/撤销/重核验；草稿读写/发布/撤回；有限最近审计记录 |
| 操作结果 | 按当前主体与operationId查询是否已提交；不暴露他人结果，鉴权在查询前；过期不存在可明确返回unknown，不能假称失败已回滚 |
| 维护 | operator授予撤销命令、幂等结果/过期数据清理入口与最近运行状态；本版不建设通用任务管理UI |

业务写的幂等scope＝environment＋gymId＋发起userId＋operationType＋随机UUID key，保存规范化body的带服务端密钥HMAC摘要、提交结果和appliedRevision，避免持久化低熵配对码或会员引用的可枚举无盐摘要。相同key/相同内容在24小时内返回原执行结果；不同内容返回409 IDEMPOTENCY_CONFLICT。原结果是操作已发生的事实，不是当前有效状态；回复携带当前revision或要求刷新。鉴权、账号／角色撤销与当前访问权限检查优先于返回缓存结果。配对码展示只允许请求仍有效且属于本人；删除操作成功后的旧会话不因幂等查询恢复有效。

所有新写请求需要expectedRevision（创建用expected absent）和requestCreatedAt；服务端校验时间窗口，不允许过期请求因幂等台账清理而重新执行。已提交请求在台账有效期内可查询原结果，不重新检验为新写。客户端不能自动更换key、时间或expectedRevision。观察响应丢失先查询；查到已提交只刷新；查无记录且超60秒必须重新观察。其他写超过5分钟须刷新当前状态、用户再次确认新操作。冲突时保留未提交表单供核对，刷新版本后由操作者明确决定，不自动重放旧覆盖。

| 状态 | 客户端处理 |
| --- | --- |
| 200/201且业务成功 | 展示提交结果，刷新当前资源版本 |
| 400/422校验失败 | 指出字段错误，不写入、不伪成功 |
| 401会话失效 | 清个人缓存、公共浏览继续；用户主动重登 |
| 403无权／角色撤销 | 退出管理操作并提示无权限，不自动重复 |
| 409版本／唯一性／幂等内容冲突 | 显示冲突、重新读取；不覆盖／抢绑 |
| 410请求到期／消费／取消 | 显示终态，必要时由用户重建；不复活旧码 |
| 429限流 | 显示服务端重试时间，不通过重启／换会话清零 |
| 5xx／超时／网络断开 | 读显示不可确认；写标“结果待确认”，查询操作结果后处理；不假称写入已失败或成功 |

`wx.request success`仅说明收到响应，必须再判断HTTP和业务码。[网络官方依据](../../raw/SRC-20260916-gym-wechat-06.md)。数据写入、对应审计及幂等结果同事务提交；审计写失败则业务写也失败。配对绑定／发布／删除与角色变更需服务端并发约束，CP0选择的数据库必须支持所需原子性或提出等价可验证方案，不得降低业务保证。

## 9. 保留、清理、账户删除与当前快照例外

以下是产品实现参数，不是法定期限或已对外法律承诺。默认无自动备份体系，不声称可以从备份恢复或即时擦除所有副本；未经后续批准不建立额外数据备份。若托管数据库自带备份，CP0须记录实际副本、保留周期及可执行删除边界，未核实前不得向真实用户承诺全副本即时删除；这不阻塞本地工程，但阻塞CP6真实数据说明一致性验收。

| 对象 | 在线保留与清理规则 | 当前快照例外／删除作用 |
| --- | --- | --- |
| 观察事件历史 | 以publishedAt起30天，到期后下次小时任务分批删除 | 当前指针／revision／控制状态、当前最后一次观察的level/observedAt/validUntil保留直到被替换或门店服务结束；不含actor且从不续TTL；可显示很旧历史但不能标新鲜 |
| 课程历史发布／修订 | 退出当前状态且覆盖结束后30天清理；当前草稿与当前发布保留 | 当前快照／撤回标记／revision保留，避免清理回退上周表；不含个人微信身份 |
| 配对请求 | 600秒后即失效；终态及加密码于下次小时清理；查询摘要不得保持可用 | 成功消费的必要事实转成不含码的业务审计，不能因删除请求而再次消费 |
| 限流桶 | 窗口结束后1小时清理；未到期桶保留在DB跨重启 | 登录全局60秒桶同理；清理失败只延长存储，不延长阻断窗口 |
| 会话 | 即时按期限／revoked判定；终止后24小时内清除摘要和历史会话字段 | 删除账号即时撤销全部会话，清理过程不能令其复活 |
| 幂等台账 | 创建后24小时，后续小时清理；不因重放延长 | 不保留原始会员引用、code或完整令牌；短时配对展示副本另外受600秒终态约束 |
| 操作审计 | 90天，小时清理；只存业务动作、结果、revision、时间、原因类别及必要业务actorId | 不存openid、原始会员引用、配对码／令牌／凭证；账户删除后actor/subject关联改为“已删除账户”，保留操作事实 |
| 当前MemberRegistry | 保留最小memberKey、资格/期限、核验时间、revision，供唯一性和撤销检查；历史解绑关联30天清理 | 这属于馆方当前资格防重绑快照，账户删除不自动取消原馆合同；revoked最小防回生记录保留到馆方显式重新核验恢复或门店服务结束，不能随90天审计清理而复活 |
| 当前Binding和微信映射 | 有效业务关系期间保存；解除绑定立即失效，历史关系30天清理 | 删除账号即时失效，随后按下方删除任务清除个人关联；新登录不按旧openid恢复关系 |

**删除语义**：本人新鲜认证并明确确认后，客户端先生成并保存至少256位安全随机删除回执令牌，只把其摘要随删除请求送服务端；单事务将账号置deleting、撤销全部会话、移除operator、使Binding及待配对请求失效并创建持久化删除任务。此时返回“账户已停用，数据清理处理中”；不是宣称所有记录已物理删除。客户端清理个人缓存，只保留该回执；提交响应丢失也可用原回执查询pending/completed/failed，不需要已撤销的业务会话，也不返回个人资料。服务端只存回执摘要，回执完成后7天失效，日志不记录完整回执；查无任务时不假称已删除，仍须按原请求是否提交处理，不自动新建第二次删除。

持久化删除任务每小时处理，失败下个小时重试，正常完成目标≤24小时；超过24小时仍未完成标为处理延迟，保留deleting拒绝访问，维护者可用同一任务id重试，不能将失败视为删除完成。任务清除微信映射、个人账户字段、Binding个人关联、会话／配对／个人幂等数据；将业务审计actor/subject去关联，再最小化保留已删状态回执。**当前MemberRegistry仅保留上述防重绑最小快照，不带userId／openid**，删除说明明确这不是对原馆资格登记／合同的注销，也不把memberKey谎称不可关联。

删除接受到完成期间，相同微信身份登录返回ACCOUNT_DELETING，不新建；完成后新的主动登录允许新userId。CP0需选择可执行的临时删除锁／映射保留方式，在deleting期间受限保留映射用于阻止重建，完成事务再清除；不是无限保留微信身份。删除与写入竞争按提交顺序完成，所有未提交旧用户写必须再次检查并失败。清理任务重启后从持久化进度续做，重复执行结果一致；小程序被用户在微信中移除不等于本业务账户删除。

小时清理采用有界批次和事务进度，失败只重试未完成批次，当前快照不成为误删除目标。维护端最近操作记录最多100条且仍受90天窗口；清理运行状态由部署维护者查看，不增加数据运营平台。工程测试必须以受控时钟／造旧记录证明边界、例外、失败与重启恢复，不能仅展示清理函数存在。

## 10. 隐私流程适用性

首版不主动采集姓名、手机号、头像、位置、人脸、凭证原图或运动健康数据；配对手输不要求相机，公共浏览不弹会员授权。后台处理微信映射、memberKey和状态仍属于个人信息处理，不能因为不调用手机号就填写“未采集隐私”。真实主体、联系渠道和用途说明在CP6前与实际处理字段一致。

用户点击会员登录／绑定前提供清楚说明和可打开的隐私指引，拒绝保留公共浏览。应用自己的知情同意记录按说明版本保存，不等于微信平台隐私接口授权；只在实际调用涉及的隐私API时，检查后台声明、平台同意状态和基础库支持，按官方流程触发同意，不能以普通checkbox伪造微信同意。`wx.login`本身不被本PRD泛称为必须取手机号／昵称的授权；未调用的敏感能力不为凑流程索取权限。[官方指南](../../raw/SRC-20260916-gym-wechat-04.md)

如果所需平台隐私能力未声明、不支持或用户拒绝，停止相关操作、说明原因，不循环弹窗或降级成假授权；不受影响的公共功能继续。扩展隐私用途或字段需新版本说明与适用的重新同意，本版不顺带新增能力。CP6验证真实配置与拒绝路径，CP5工具测试不冒充官方平台实际通过。

## 11. 验收、试点与未决项
